# Следующие шаги — исследование, не календарный план разработки

1. **Получить реальную структуру данных.** Посмотреть таблицы и папки ПТО, реестры ИД, акты, журналы, спецификации, сметы, подрядчиков, историю исправлений. Реальные коммерческие данные сначала обезличить.
2. **Разобрать связи.** Определить идентификаторы объекта, этапа, работы, материала, подрядчика, документа; установить источники фактов и правила версионирования.
3. **Выбрать сценарий пилота.** Один понятный комплект ИД и 2–3 вида проверок с наглядным результатом.
4. **Уточнить применимые нормы.** Проверить 344/пр, профильные СП/ГОСТ, региональные и отраслевые акты; определить юрисдикцию, тип объекта, дату начала работ.
5. **Протестировать ИИ.** На обезличенном комплекте оценить извлечение, нахождение ошибок, полноту ссылок на источники, ложные замечания.
6. **Сформировать технические границы.** Изоляция заказчиков, права доступа, псевдонимизация, аудит, нормативный updater, подтверждение человеком.
7. **Собрать прототип реестра ИД.** Фильтры, связи, история, замечания, утверждение ПТО, экспорт актов/форм без имитации проведённых работ.

Оценивать измеримо: время подготовки, процент выявленных несоответствий, долю ошибочных замечаний, полноту комплекта, повторное использование уже внесённых данных.
