# Инженерный план: от существующего PoC к MVP

**Базис:** [согласованные решения 18.11.2026](../decisions/2026-11-18-product-contract.md). Каждая стадия имеет файл результата, код, acceptance и негативный сценарий. Даты намеренно не обещаем: финализация зависит от качества тестового корпуса, эксперта ПТО и режима обработки данных.

## Итерация 0 — защитить контракт продукта и подготовить эталон

**Результат:** каталог 10–20 синтетических файлов разных типов, включая сложную таблицу, PDF с разделами, недостающий документ, несовпадающую редакцию, похожие шкафы/позиции, файл с метаданными автора и скан без текстового слоя.

**Артефакты:** `fixtures/` только синтетика; `docs/contracts/`, `docs/decisions/`; инструкция о происхождении данных.

**Проверка:** ни одного закрытого оригинала/реального реквизита в git. Для каждого тестового случая есть ожидаемые сущности, ошибки и разрешённый outbound.

## Итерация 1 — F01: весь пакет и отдельный тип каждого файла

**Сделана первая часть 18.11:** `batch.py::discover_files`, `document_types.py`, `vault.py::stage_file/classify_document`, кнопка «Загрузить всю папку», отдельный `QComboBox` типа в Windows UI и синтетические тесты. **Не сделаны:** полноценный manifest статусов/связей, профили по типам, локальное безопасное обезличивание, структурная AI-копия и поддержка больших файлов.


| Порядок | Конкретный модуль | Что сделать | Критерий |
| --- | --- | --- | --- |
| 1 | `construction_docs/batch.py` | **PoC код:** рекурсивный перечень, исключение симлинков, лимиты; staging шифрует оригиналы. Остался персистентный manifest/контроль сумм | 50 синтетических файлов в одной операции; все учтены |
| 2 | `construction_docs/document_types.py` | **PoC код:** 24 варианта типа; версии parser profiles ещё нет | Ни один новый файл не отмечается как классифицированный без выбора ПТО |
| 3 | `construction_docs/desktop.py` | **PoC код:** кнопка загрузки папки, тип (combo per row), статус. Нужны UX/пакетная фильтрация/тест на Windows | Можно выбрать тип отдельно для 50 строк, не раскладывая по папкам |
| 4 | `construction_docs/ingest.py` | Адресуемые `SourceFragment`, PDF page, XLSX sheet/cell, DOCX table/paragraph | Каждое извлечённое поле имеет источник |
| 5 | `construction_docs/metadata.py` | Реестр извлечённых, скрытых и недоступных метаданных | Непроверенные атрибуты отображаются, а не пропадают |
| 6 | `tests/test_batch.py` | Ограничения на размер, неизвестный формат, неполный пакет, неверный тип | Fail-closed, никакого импорта с опасными обходами путей |

**Нельзя выдавать за MVP**, если отсутствует обработка выбранных типов или невозможно учесть каждый исходный файл.

## Итерация 2 — безопасная структурная копия (F01→F04)

| Модуль | Реализация | Приёмка |
| --- | --- | --- |
| `construction_docs/aliases.py` | Шифрованная локальная `real_id → alias` карта, область проекта и тип сущности | Одинаковая сущность стабильна, похожие фамилии не сливаются |
| `construction_docs/structured_packet.py` | Поля, геометрия, связи, разрешённые метаданные; типизированные placeholders | Структура каждого source fragment представлена или явно blocked |
| `construction_docs/policy.py` | Типизированный allowlist по document type/task, проверка всех значений, metadata и связей | Запрещённое поле или произвольный user/system prompt отклоняются |
| `construction_docs/coverage.py` | Manifest на весь объём и статусы imported/parsed/filtered/approved/analyzed | Сумма статусов сходится с количеством файлов/фрагментов |
| `tests/test_structured_packet.py` | Leak tests: ФИО, author metadata, скрытая Excel-ссылка, номер документа, сочетания технических полей | Шлюз не выпускает неизвестный контекст |
| `server/gpugo_edge/app.py` | Новый versioned API, tenant auth, response validation и строгая схема | Сервер не доверяет клиенту, не принимает произвольные поля |

**Технический риск:** нужные для семантики параметры могут одновременно идентифицировать объект. Нельзя делать вид, что простое переименование подрядчика гарантирует защиту.

## Итерация 3 — F02/F03: graph + rule engine + документарный анализ

1. Определить `SourceDocument → SourceFragment → Claim → Entity` с provenance, версиями и статусом.
2. Задать отдельно `design / as-built / measurement / reported / normative / AI-suggestion`; не смешивать значения разной доказательной силы.
3. Реализовать ребра `Drawing→WorkItem→Equipment/Material→Act→Protocol→RegisterEntry` и очередь неоднозначного сопоставления.
4. Детерминированно сверять арифметику, типы, редакции и наличие обязательных оснований.
5. Передавать AI допустимый **структурный контекст**, требовать ссылку на `source_ref` и `rule_id`.
6. На выходе по каждому finding иметь: исходное и ожидаемое значение, источник, версию, категорию, статус и явно нерешённые вопросы.

**Acceptance:** сквозная история от синтетической спецификации до АОСР/реестра; неизвестная связь не выдумывается.

## Итерация 4 — F06: структурный результат → настоящая форма

1. Версионировать `TemplateDefinition` по типам документов/этапам.
2. AI возвращает **не бинарный PDF**, а `PreparedDocument` с `field_id`, `source_ref`, `template_version`, псевдонимами и статусом.
3. `validate_result()` отклоняет лишние поля, несуществующие ссылки, неправильные placeholders, забытые обязательные реквизиты.
4. Локальный `alias_resolver` подставляет реальные данные **адресно по ID поля**.
5. `renderer` собирает DOCX/XLSX/PDF по утверждённому шаблону, сохраняет manifest/hashes.
6. ПТО проверяет и утверждает **только готовый комплект**. Обратная связь запускает новый цикл.
7. Отдельно проектировать юридическую подпись/ЭП и полномочия; не симулировать её.

**Acceptance:** реальная сущность никогда не попадала на GPUGO, но в итоговом локальном файле корректно отображена; матрица field↔source не потеряна.

## Итерация 5 — F07: нормы и эксплуатация

- Подключить подтверждённые источники и право доступа; все редакции immutable.
- AI ищет обновления, парсит редакции; независимая проверка статуса/дат/применимости перед публикацией правил.
- UI показывает `last_successful_verified_update`, `last_attempt`, `stale` и ошибку отдельно.
- Проверить влияние изменений на текущие проекты, без переобработки всего архива без необходимости.
- Windows packaging/signing, backup/restore, hardening, аудит; GPUGO inference GPU benchmark и нагрузка.

## Честная инженерная граница

Сегодня код: **локальный Windows PoC + базовый importer + SQLite/Fernet/DPAPI + узкие проверки реестра + enums-only AI gateway + FastAPI edge demo**.

**Не реализовано:** структурное обезличивание, per-file dropdown для batch, alias resolver, полноценный нормативный updater, F06 renderer, проверка полного объёма, production auth, рабочий 4×6000D inference. Не переписывать текущий README так, будто это уже существует.

## Что проверять на каждой стадии

- Оригинальные файлы не перезаписываются.
- История норм и документов восстанавливается.
- Все файлы в manifest, blocked учитываются.
- Никакие секреты не появляются в логах, запросах, трассировках.
- Нет самовольной подстановки фактов, значений измерений и подписей.
- Неверный ответ AI не меняет рабочую БД.
- Сбой GPUGO не лишает пользователя локальных документов.
