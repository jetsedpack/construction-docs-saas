# Объём и обязательные ограничения

> Ранняя постановка PoC. Актуальный продуктовый контракт — [решения 18.11](../decisions/2026-11-18-product-contract.md); реализованный код и цель не смешивать.

**Вход:** кейс ЧГЭС, пояснения автора схемы от 18.11.2026. **Выход:** Windows-приложение, локальная «коробка», локальные правила, защищённый выход к инференсу GPUGO, проверка ПТО, формирование ИД.

## Продуктовая модель
- Только **Windows 10/11 x64** (для пилота Windows 11), desktop UI. Не PWA, не мобильное приложение. Без браузерного кабинета в MVP.
- Рабочее место: инженер ПТО. Следом роли руководителя ПТО, проверяющего, администратора проекта, подрядчика; **общая многопользовательская работа не входит в первый локальный MVP**.
- Каноническое состояние — структурированный защищённый реестр, а не имена файлов на диске и не ответ LLM.
- ИИ **обнаруживает**, **обосновывает**, **предлагает**. Человек принимает или отклоняет; реальное выполнение работ, измерение, подписание и согласование ИИ не совершает.
- Два контура: **доверенный локальный Windows** (сырые документы/ключи/связи/реестры) и **GPUGO inference** (только разрешённый контекст, без долговременного хранения исходных документов).
- Начальный путь — локальное приложение + подключение по HTTPS. Позднее: customer-hosted «коробка» с PostgreSQL и коллективным доступом с Windows-клиентов; **не переносить её на GPUGO по умолчанию**.
- Исходные РД могут быть ошибочными и противоречивыми, поэтому «проектное» и «фактическое» не смешиваются.

## Что реально поддерживается в PoC-коде
1. Импорт PDF с текстовым слоем, DOCX, XLSX и CSV с ограничениями ресурсов.
2. Шифрованное хранение оригинала и извлечённого текста на Windows; ключ защищён DPAPI текущего пользователя.
3. Локальные проверки реестров: последовательность страниц, расхождение числа листов, отсутствие служебных реквизитов (не равнозначно нарушению).
4. Вывод находок инженеру в Windows-интерфейсе.
5. Контракт строго типизированного шлюза к OpenAI-совместимому API GPUGO: передаёт только коды проблем и обезличенные числовые параметры, **не документы и не текстовые выдержки**.

## Чего **нет**, и это нельзя заявлять как готовое
- Доказанного юридического соответствия всех НПА/НТД, автоматической ЭП, согласований, OCR, BIM/IFC, DWG, EDI/1С, закупок и бухгалтерии.
- Универсального распознавания любых РД, промышленной авторизации нескольких организаций, 152-ФЗ/187-ФЗ compliance по факту кода.
- Проверенной защиты от всех способов восстановления личности по косвенным строительным признакам.
- Реальной проверки vLLM на 4×6000D, SLO/цены/пропускной способности и гарантированных моделей.
- Готового Windows-инсталлятора с подписью, обновлением, авто-backup и безопасным восстановлением.

## Доменные цели после MVP
- Документы -> объект -> шифр РД и редакция -> раздел -> оборудование -> виды работ -> исполнитель -> материал и партия -> акт -> реестр -> доказательства -> ПНР.
- ЖВК = журнал входного контроля, АОСР = акт освидетельствования скрытых работ, ПНР = пусконаладочные работы. КС-2 учитывать отдельно как документ о приёмке выполненных работ, не как универсальный синоним АОСР.
- Ключевые проверки: совместимость материала со спецификацией; шифры РД; актуальность документов качества; отступления; согласования; правильность актов и прав; комплектность ИД; связь монтажа и ПНР.
- Показать человеку «доказательную цепочку»: документ, страница/ячейка, исходное значение, сопоставленное значение, правило/редакция нормы, предложение, решение.

## Политика данных
Не коммитить реальные документы ЧГЭС, подлинные ФИО/адреса, номера договоров и конфигурационные файлы шкафов. В репозитории — только синтетические примеры, абстрактная предметная модель и ссылки на исходный Google Drive (не копии).
