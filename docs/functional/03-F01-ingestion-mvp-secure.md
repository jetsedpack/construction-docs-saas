# F01 — массовая загрузка и классификация документов поштучно

**Согласованное продуктовые требования:** инженер сбрасывает **весь пакет РД одним действием**, после чего **для каждого файла вручную выбирает тип из справочника «коробки»**. Программа не заставляет вручную раскладывать по папкам; при этом выбранный тип управляет профилем локального парсинга, распознавания полей и маскирования.

**Два уровня:** MVP и усиленный защищённый контур. UX одинаков, отличаются глубина анализа, запреты и гарантии проверки.

## Функциональная цепочка

1. **Массовый вход.** Выбрать папку / группу файлов (позже безопасная загрузка архивов). Рекурсивно составить manifest: исходный относительный путь, размер, хеш, формат, версия, статус; доступ только внутри изолированного аппендикса «коробки».
2. **Сохранение оригиналов.** Сохранить неизменённые байты в локальном шифрованном хранилище. Исходный путь не становится внешним ID.
3. **Экран классификации.** Показать одну таблицу: файл, расширение, выбранный из выпадающего списка **тип документа**, профиль обработки, статус; до явного выбора типа документ **не готов** к отправке на ИИ. Для каждого файла нужен собственный выбор. Поиск по каталогу типов допустим.
4. **Выбор профиля по типу.** Справочник «коробки» сопоставляет `DocumentType → ParserProfile → ExtractionSchema → SensitiveFieldPolicy → OutputSchema`. Формат файла (PDF/XLSX/DOCX) и предметный тип (РД/спецификация/АОСР) — **разные признаки**.
5. **Локальный разбор.** Прочитать страницы, листы, таблицы, ячейки, подписи, графику и атрибуты в пределах поддержанных возможностей. Каждый извлечённый фрагмент привязать к оригиналу: файл+версия+страница/ячейка+диапазон.
6. **Локальное обезличивание.** Извлечь прямые идентификаторы, использовать закрытый словарь соответствий (например, `ИП Иванов ⇄ ИП 1849`). Замены устойчивы в рамках проекта, одинаковая сущность сохраняет один alias в разных файлах.
7. **Сборка обезличенного представления.** Не переписывать PDF поверх оригинала: создать **структурированную копию для ИИ**: все извлечённые поля (в том числе замаскированные placeholders), связи, порядок, расположение элементов и безопасные метаданные. Это **не пересобранный PDF/DOCX/XLSX**; бинарный оригинал остаётся в защищённом аппендиксе. Адреса фрагментов и связи сохраняются, но неразрешённые значения/раскрывающие метаданные на GPUGO не отправляются. Имена локальных файлов, точные пути, закрытые реквизиты и сам словарь не передавать.
8. **Проверка пропусков и защищённости.** Для каждого файла `ready | blocked | needs_attention`, с причиной: не выбран тип, нет профиля, повреждение, скан, неизвестная графика, возможный идентификатор, недостаточная полнота.
9. **Шлюз → GPUGO.** Только разрешённая структурная копия с безопасными метаданными и применимыми правилами/формами «коробки». ИИ составляет обезличенный структурированный рабочий результат в предусмотренном формате. По возвращении через шлюз ответ валидируется и сохраняется как промежуточная версия; **только локальный resolver подставляет настоящие реквизиты и рендерит документы по шаблону**. Оригинал не трогаем.
10. **Индекс охвата.** Должен отличать `imported`, `classified`, `parsed`, `deidentified`, `gateway_approved`, `AI_processed`, `verified`. 100% импортированных файлов не означает 100% безопасно проанализированных.

## MVP: минимально реализуемый и проверяемый

| Подфункция | Решение |
| --- | --- |
| Пакетная загрузка | Windows FileDialog/FolderDialog, рекурсивный просмотр без распаковки сторонних архивов |
| Классификация | Явный выбор типа **каждого** файла в таблице; не автосортировка вместо ПТО |
| Типы | Закрытый стартовый каталог 5–8 видов: РД, спецификация, ведомость, реестр ИД, акт, сертификат, протокол ПНР и др. — окончательно согласовать |
| Форматы | Только реально поддержанные PDF с текстовым слоем, DOCX, XLSX, CSV; неподдержанные остаются в хранилище со статусом `blocked` |
| Разбор | Локально, ограничение размера и количества страниц, с адресом исходного фрагмента |
| Обезличивание | Whitelist полей по типу + локальная псевдонимизация известных реквизитов; **не доверять одной регулярке как гаранту защиты** |
| Сборка | Структурированный JSON для ИИ: поля, безопасные метаданные, расположение (page/sheet/cell/relative geometry), связи, version/rule/template IDs, placeholders. Подлинные source ID остаются в Windows |
| Отправка | Вне PoC только после явного разрешения; при неопределённой безопасности `blocked`. В существующем коде remote adapter принимает **только категории замечаний и числа**, полноценную отправку текста реализовать отдельно |
| Ошибки | Отображение неразобранных/заблокированных файлов, возврат на классификацию и ручная проверка без автоматической отправки |

**Важное ограничение:** это MVP функциональности, а не разрешение обрабатывать реальные закрытые файлы без security review. Маскирование текстовых полей не гарантирует защиту чертежей, PDF-метаданных и редких технических характеристик.

## Усиленный защищённый контур

| Требование | Дополнительный контроль |
| --- | --- |
| Несколько представлений файла | Проверять embedded attachments, OCR-слой, изображения, комментарии, скрытые Excel-листы, свойства DOCX/PDF, EXIF/метаданные, формулы и ссылки |
| Парсинг опасных файлов | Изолированные процессы/sandbox, файл-сканирование и лимиты распаковки/памяти/времени |
| Псевдонимы | Контекстные устойчивые ID внутри проекта, защита словаря, обратная подстановка только при локальной авторизации |
| Безопасность содержимого | Детектирование косвенных идентификаторов, оценка возможности восстановления объекта по сочетанию полей |
| Выход через шлюз | Отдельные версии политики по типу документа и задаче; независимая серверная проверка DTO, аутентификация и квоты |
| Прослеживаемость | Для каждой части: source file/page/cell, статус обработки, версия policy, hash обезличенного результата и журнал запроса |
| Полнота | Отчёт по всем файлам, страницам, таблицам, медиа, неподдержанным элементам и пропускам |
| Операционная безопасность | Модель угроз, BitLocker/NTFS/ключи/бэкапы, поставка приложения, tenant isolation, pentest |

## Пример преобразования

Исходная запись в защищённом аппендиксе:
`ИП Иванов; договор № X-17; кабельная линия L-11; длина 33 м; РД rev.2`.

Локальный словарь (наружу **не** передавать):
`ИП Иванов → ИП 1849`, `договор № X-17 → CONTRACT-204`. Обозначение линии тоже может раскрывать объект, поэтому отправка его как есть **не подразумевается**.

Безопасный контекст под конкретную проверку может выглядеть так:
`contractor_alias=ИП 1849; drawing_revision=2; planned_length_m=20; recorded_length_m=33`.

**Это лишь пример целевого формата.** Его реальная допустимость требует проверки на реидентификацию и утверждения политики. Локальный исходник и словарь доступны коробке для **обратной подстановки чувствительных реквизитов после AI-анализа**; модель их не получает. Готовые DOCX/XLSX/PDF формирует локальный renderer по формам «коробки», а не исходный парсер.

## Статусы реализации

- Теперь есть **PoC** `desktop.py::import_batch` (папка целиком и `QComboBox` по строкам), `batch.py::discover_files` (файлы и лимиты), `document_types.py` (черновой каталог типов), `vault.py::stage_file/classify_document` (оригинал шифруется до выбора типа, парсер запускается после); `ingest.py::extract` поддерживает часть форматов. Это нужно испытать на Windows.
- **Ещё нет** полноценного каталога `DocumentType → ParserProfile`, OCR/CAD, локального словаря aliases, безопасной реконструкции и проверки структурного пакета, рабочих автоматических AI-итераций и полного аудита охвата.
- **Никакой** из новых блоков нельзя маркировать на схеме «работает» до появления кода и тестов.
